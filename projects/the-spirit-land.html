The Spirit Land

EEG-Controlled First-Person Interactive Experience

The Spirit Land is a first-person brain-computer interface (BCI) game triggered by electroencephalography (EEG)-based relaxation and focus. EEG is a non-invasive way of reading electrical activity from the scalp; in this project, those signals were translated into forward movement, environmental triggers and a meditative exploration loop.

( bci / eeg )

What BCI and EEG mean in this project

A brain-computer interface, or BCI, is a system that lets a computer respond to brain activity instead of relying only on physical input such as a mouse, keyboard or controller. In The Spirit Land, that meant the player could influence walking and environmental events through mental state rather than button presses alone.

EEG, or electroencephalography, is the non-invasive sensing method used here. Electrodes placed on the scalp measure electrical activity in real time. This project focused on Alpha and Beta bands because Alpha rises were useful for relaxation-based triggers, while Beta rises were useful for concentrated forward movement.

BCI, in practice

A live control loop where the player learns how to shape mental state and the system learns how to translate that signal into readable gameplay behaviour.

EEG, in practice

A portable non-invasive signal source that is powerful enough for creative interaction, but noisy enough that calibration, thresholds and fallback controls have to be designed carefully.

OpenBCI GUI

Band Power was the main live EEG reference during calibration

The OpenBCI Band Power widget visualised delta, theta, Alpha, Beta and Gamma activity in real time. In the project workflow, it acted as the fastest way to see whether relaxation or concentration was rising strongly enough to support the next interaction state.

( premise )

A dual-state BCI journey built around focus and relaxation

The project began with one core idea: instead of treating BCI control as a single abstract mental-state input, different brain states should do different jobs. In The Spirit Land, Beta activity supports locomotion, while Alpha-based relaxation unlocks environmental responses such as bridge reveals, spirit interactions and other world changes.

That separation let the system alternate between active control and calm attention, which made the interaction easier to read and more meaningful than a one-signal prototype. The first-person format was chosen to deepen immersion in the present build while also leaving room for future VR adaptation.

World Regions

Spirit Lake, Flower Sea and Dynamic Forest were used as themed spaces for movement, atmosphere and BCI-triggered discovery.

( world design )

Three regions carried the atmosphere of the thesis into the playable build

The thesis was not only about signal processing. A large part of the project involved building regions that felt calm, symbolic and visually readable enough for BCI interaction to make sense.

Spirit Lake

The calm anchor of the world

The lake region established the game’s meditative tone through open space, soft lighting and a readable magical trigger area that invited slower interaction.

Flower Sea

A softer field built for wonder and pause

The Flower Sea pushed the environment toward a more dreamlike mood, using dense floral coverage and bright trigger energy to make the scene feel rewarding rather than purely decorative.

Dynamic Forest

A denser region for contrast and progression

The forest introduced a more enclosed visual rhythm, giving the world a stronger sense of variation and helping the project move beyond a single mood or one-scene prototype.

Bridge Trigger

Relaxation could turn the bridge from absence into access

The bridge scene was one of the clearest examples of Alpha-driven interaction design. Instead of using relaxation as a hidden background metric, the game visualised success by opening a path forward, letting players feel that calm mental control had physically changed the world.

( interaction model )

Movement, puzzles and accessibility were designed as one system

Beta Locomotion

Real-time Beta band power was routed into Unity and compared against an adjustable threshold so walking could be triggered through focused mental effort rather than a standard controller alone.

Alpha Relaxation Events

Relaxation state was used to unlock environmental responses, including puzzle-like reveals and magical feedback moments that made the world feel reactive rather than decorative.

Hybrid Control

Keyboard fallback stayed available throughout the experience so player agency was never blocked by unstable signal moments or participant fatigue.

( training & support )

Calibration was treated as part of the experience, not a barrier

To make the system more playable, I built separate training scenes for relaxation and focus. The relaxation scene used strong visual feedback plus an audio confirmation so participants could close their eyes and still know when the threshold had been reached. The focus scene showed a direct walking state response and supported threshold tuning.

Support tools were then layered in around those scenes: optional 20 Hz flicker for Beta activation, Alpha and Beta binaural support, gameplay music, a threshold dropdown and live brainwave readouts. Together, these features turned calibration into a guided interaction rather than a hidden technical step.

Player Support Tools

  • Threshold personalisation for Beta walking.
  • 20 Hz flicker support for focus activation.
  • Binaural audio support for Alpha and Beta modes.
  • Live band readouts and on-screen relaxation status.

Why It Matters

The project was not only about making EEG work technically, but about giving players enough guidance to stay calm, understand the system and keep moving through the experience.

( onboarding & integration )

Player guidance and technical wiring were both part of the design

In-Game Guidance

The build explained itself before asking the player to perform

The help menu sat inside the experience instead of outside it. It reminded players to complete relaxation and focus training first, clarified the hybrid control scheme, and made the OpenBCI connection requirements visible before play began.

Unity Integration

Unity listened for cleaned EEG data through a dedicated receiver

On the implementation side, the OpenBCI receiver inside Unity listened on port 3059 for re-formatted data forwarded from Python. That let the project separate raw signal handling from gameplay logic while keeping the control loop responsive enough for live interaction.

( evaluation )

Small-scale testing showed strong atmosphere and useful support tools

The project was evaluated through a four-participant pilot study combining survey feedback and qualitative observation.

Participants

4

All participants were new to BCI interaction, making the test especially useful for readability and first-time usability.

Environment Response

100%

Every participant described the world as peaceful, calming or relaxing, confirming that the visual and audio atmosphere was doing real work.

Support Tool Value

75%

Most participants found the binaural support useful for relaxation or concentration, and the 20 Hz flicker was also widely reported as helpful.

Control Preference

50 / 50

Half preferred Beta walking while half preferred keyboard movement, which validated the decision to keep hybrid fallback inside the final build.

( showcase )

Installation, participant testing and live presentation

Installation

Showcase-ready physical setup

The final setup combined the main display, support monitor, BCI hardware and printed research framing so the project could be experienced both as a game and as a public-facing research installation.

Participant Testing

Eyes-closed relaxation trial

This test condition was important because Alpha-state interaction only works if the player can relax without needing to keep reading the screen. That is why the build included clear audio confirmation.

Public Presentation

Explaining the project at the MMT showcase

Beyond the playable build, the project also needed to communicate itself clearly in person. Presenting it live demonstrated public presentation skill as well as the ability to explain the technical pipeline, user experience logic and research rationale to mixed audiences around the project.
