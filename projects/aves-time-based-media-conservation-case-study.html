( project overview )

Project overview

AVES, or Audiovisual Environment Suite, is an interactive audiovisual software work by Golan Levin developed around 1998-2000. Across the suite, user input shapes visual behaviour and synthetic sound in real time, which means the artwork's identity is tied not only to recorded appearance, but also to executable software, interaction logic and historically specific computing conditions.

In this case study, the practical technical examination was carried out on the historical Yellowtail documentation movie retrieved from the MIT Media Lab AVES archive. That media-level work was then used as one evidence source within a wider conservation analysis focused on artwork identity, significant properties, dependencies and preservation strategy.

What AVES links together

Real-time visual generation, synthetic sound and embodied user interaction rather than a fixed linear audiovisual output.

Why that matters

Preserving documentation alone can record examples of behaviour, but it does not preserve the generative and interactive structure that produces the work.

( conservation question )

Conservation Question

How can an interactive audiovisual artwork remain authentic and reproducible when its original software and technological environment become obsolete?

This case study treats that question as both a media-preservation problem and an artwork-identity problem, because software execution, interaction behaviour and historical context are all part of what has to be preserved.

( qc review )

QCTools and human audiovisual review

QCTools signal changes were manually reviewed against the actual audiovisual content rather than being treated as faults on sight. The main variations aligned with intentional content changes within the historical documentation movie.

  • Explanatory and narrated sections.
  • Audiovisual demonstrations.
  • A transition to black near the end of a demonstration.
  • Return of narration.

Sampled review result

No obvious unintended visual freezing, audio dropout or perceptible decoding artefacts were identified during the sampled review.

QCTools Overview

Signal variation was interpreted in relation to content, not only graphs

The QCTools overview was used as a screening layer for waveform, chroma and level changes, then checked against the moving-image and audio content itself. That prevented intentional transitions and demonstration segments from being misread as preservation faults.

( preservation strategy )

Preservation strategy

Emulation should be investigated first where possible, because it offers the potential to retain historical software behaviour without immediately rewriting the work. That makes it the strongest first hypothesis for a software-based artwork whose behaviour is bound to historical execution conditions.

However, successful emulation does not automatically equal successful preservation. Any emulated result would still require validation against the artwork's interaction behaviour, response timing, rendering qualities, sound synthesis and overall experiential properties.

Primary position

Emulation first, then validate whether the emulated result still feels, sounds and behaves like the historically meaningful work.

Emulation

Best starting point where historical software behaviour can still be retained without rewriting the work immediately.

Migration

May be considered where emulation is impractical, but it risks altering historically significant software behaviour.

Recordings

Should be treated as documentation and access surrogates rather than replacements for the interactive artwork.

( reflection )

Reflection

This independent professional-development project gave me practical experience in building a small but repeatable preservation workflow around a historical audiovisual file, then documenting both what could be stated confidently and what remained unresolved at artwork level.

It also helped me connect my background in audiovisual technology, interactive systems and HCI with time-based media conservation. The study pushed me to think beyond file integrity alone and to reason more carefully about software-art identity, significant properties and the difference between preserving documentation and preserving behaviour.
